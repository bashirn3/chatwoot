- Static routes (`/`, `/dashboard`, `/api/openapi.yaml`) serve correctly.

## 5. Deploy mechanics

- During the initial deploy, France Central hit a transient Kudu 504 polling bug.
- Swapped to **async deploy with HTTP-based readiness checks**:
  - `az webapp deploy ... --async true --track-status false`
  - Poll `/api/health` until it returns `200` (or `401`, indicating app is up but endpoint is protected).
- Re-running `./deploy.sh` remains fully idempotent.

---

## 6. Notes worth flagging

- **Finland data residency caveat:** Azure has no Finnish datacenter. `wasup-fi` physically runs in Sweden Central (Gävle). If hard FI residency is ever required, add a Hetzner Helsinki or GCP `europe-north1` node dedicated to FI.
- **Cost (B1 SKU):** ~€12 / month × 8 ≈ **€96 / month**.
- **Scaling per region:** bump to B2 with:
  ```bash
  SKU=B2 ./deploy.sh
  ```
  (Do this for any region that ends up hosting a lot of WhatsApp numbers.)

## 7. Quick ops cheatsheet

```bash
# Load env (URLs + API keys)
source infra/azure/keys.env

# Health check all regions
./infra/azure/health.sh

# Tail logs for one region
./infra/azure/logs.sh de     # or fr / it / fi / se / no / uk-south / uk-west

# Restart one region
./infra/azure/restart.sh de

# Restart all regions
./infra/azure/restart.sh all

# Redeploy (idempotent)
./infra/azure/deploy.sh

# Bump SKU for a bigger instance
SKU=B2 ./infra/azure/deploy.sh
```
